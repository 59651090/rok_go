# 顶号检测与等待重登框架设计

## 背景

用户希望在脚本运行过程中检测《万国觉醒》账号被顶（被其他设备登录踢下线）的弹窗，检测到后进入可配置的倒计时等待，倒计时结束后自动重新登录游戏。弹窗内的具体匹配逻辑由用户后续补充，本次只搭建框架。

## 目标

1. 提供一个可插拔的 `检测顶号()` 函数，当前返回 `false`，后续由用户填充图片/OCR 匹配逻辑。
2. 在脚本主流程中合适位置调用检测。
3. 检测到顶号后：
   - 上报一条 ERROR 日志；
   - 显示倒计时覆盖层；
   - 等待固定时长（默认 30 分钟，可配置）；
   - 等待期间可被 `stopChan` 中断；
   - 等待结束后调用现有 `检查游戏运行()` + `进入游戏()` 重新登录。

## 方案

采用**方案 A：在主循环中定期检测**。原因：改动最小，与现有 `游戏主逻辑()` 结构最契合，不需要引入额外线程或复杂的同步。

## 组件设计

### 1. 配置

```go
// 顶号等待时间，默认 30 分钟，启动前可修改
var 顶号等待时间 = 30 * time.Minute
```

### 2. 检测函数

```go
// 检测顶号 返回 true 表示检测到账号被顶
// TODO: 后续补充找图/OCR 匹配逻辑
func 检测顶号() bool {
    return false
}
```

### 3. 处理函数

```go
// 处理顶号 显示倒计时、等待、然后重新登录
func 处理顶号(stop <-chan struct{}) {
    错误("检测到顶号，开始倒计时等待")
    设置顶号等待倒计时(顶号等待时间)
    defer 清除顶号等待倒计时()

    select {
    case <-time.After(顶号等待时间):
    case <-stop:
        信息("顶号等待被停止")
        return
    }

    信息("顶号等待结束，尝试重新登录")
    检查游戏运行()
    进入游戏(stop)
}
```

### 4. 流程接入

在 `游戏主逻辑()` 的 mode0 主循环每次迭代开头调用：

```go
if 检测顶号() {
    处理顶号(stop)
    continue
}
```

`只帮助模式` 同样可以在循环开头加入检测，保证两种模式都能处理顶号。

### 5. 覆盖层显示

扩展现有 `wait_overlay.go`：

- 新增顶号等待状态（结束时间、是否激活）。
- 新增 `设置顶号等待倒计时()` / `清除顶号等待倒计时()` / `获取顶号等待倒计时()`。
- 在 `drawWaitCountdown()` 中：
  - 如果有顶号等待，显示红色“顶号等待: XX:XX 后重登”和倒计时进度条；
  - 否则显示普通等待倒计时。

## 错误处理

- 检测函数当前永远返回 `false`，不会误触发。
- 处理函数等待期间监听 `stopChan`，用户点击停止可立即退出。
- 重新登录复用现有 `检查游戏运行()` 和 `进入游戏()`，其内部已有游戏未运行/不在前台的兜底逻辑。

## 后续用户补充点

1. 在 `检测顶号()` 中实现图片或 OCR 匹配逻辑。
2. 如需按账号/服务器动态调整等待时间，可修改 `顶号等待时间` 变量。
3. 如需在只帮助模式、宝石模式也启用检测，可复制同样的 `if 检测顶号() { ... }` 代码块。
